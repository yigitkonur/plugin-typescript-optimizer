# Deviations from the design

The documents in this folder are the original plan and are never edited in place. This table records every place where the build differs from them. `AGENTS.md` links here.

| Where | Design says | Built | Why |
|---|---|---|---|
| Detection cache (doc 02 §3.2, doc 05 intro) | cached in .ts-optimize/.cache/detect.json | cached in $TS_OPT_HOME/cache/<repo-hash>.json | read-only commands (detect, doctor) must not write into the user's repo |
| SUMMARY.md header (doc 04 §9) | header includes duration | no scan duration in SUMMARY.md (kept in run.json timings_s) | acceptance 1.2 requires byte-identical artifacts across runs; only run, verified_on and applied may differ |
| Tier-1 tells engine (doc 05 §7) | ripgrep as speed tier, Node engine as fallback | Node engine only (JS regex over whole-file text with comment/string masking); rg is for agents | JS and Rust regex dialects differ (lookbehind, backreferences); 20 000 files scan in 1.8 s with 104 MB RSS so rg buys nothing |
| ast-grep vs regex tells (doc 05 §7) | ast-grep results cap regex confidence | when ast-grep ran for a rule its matches replace that rule's regex tells (except in .vue/.svelte/.astro, which ast-grep cannot parse); when absent the regex hits stay with confidence capped at likely | keeps the regex tier as a broad generator and the structural tier as the precision filter without duplicate findings |
| Row 1.5 F05 (doc 10 §3) | F05 without a Knip config trips the noise gate | gate does not trip on F05 (6 of 22 files reported); the gate is tested on a synthetic dynamic-handlers project (75 percent unused) | Knip 6's Next plugin covers App Router entries from the dependency alone; the design assumption was wrong, the gate logic itself is unchanged |
| Rule files (doc 06 §8) | rule fix_mode is one value per rule | optional fix_mode_by_tell map (slop-01: swallow and empty-catch tells are assisted) | slop-01 mixes an auto rethrow fix and assisted swallow/empty fixes |
| Seams (doc 06 §10) | nine seam pairs | plus type-11 over type-01 | (err as any).message in a catch fires both rules on one line; the catch-specific recipe is more precise |
| Knip toolbox (doc 02 §6) | toolbox arrives in Phase 6 | ts-opt toolbox install\|status\|remove implemented in Phase 1 | reachability audits of fixtures without Knip (F05, F17) need it; consent flag (--yes) and pinned lockfiles are unchanged |
| Row 2.2 plat-01 severities (doc 10 §4) | hard / warn / advisory for the three wrangler variants | hard / hard / advisory (a-jsonc advisory, b-toml hard, c-json hard) | doc 05 §6 defines process_env_populated=false when Node compatibility is not effective; a readable wrangler.json with no compatibility date or flags is exactly that, so unknown (warn) is reserved for unreadable configs |
| Triage sizing (doc 06/11: 40 candidates per chunk, inline up to 40) | chunk-size 40; main agent triages up to 40 inline | default chunk-size 8; inline up to 15 | measured on F02 (live row 2.3): 4-candidate chunks used 9-22 tool calls (about 3-5.5 per candidate) against maxTurns 60, so 40 per chunk could never finish; 8 stays under 70% of maxTurns at the measured worst case |
| Hooks (doc 03: 3 events / 5 handlers) | H1 SessionStart, H2 cmd-guard, H3 commit-guard, H4 fast-check, H5 agent-guard (deny only) | adds H6 cli-allow (PreToolUse Bash if Bash(ts-opt *): allow for the read-only ts-opt commands, and for verdict, findings ingest, triage and knip-overlay only while an audit-phase run was written to in the last 6 hours; never scan, since Knip loads the project's config files); H5 also pre-approves (allow) the calls it permits and covers Grep/Glob | live row 2.3: headless subagent calls were denied by the permission system, and the audit skill's allowed-tools grant lapses when a background subagent's completion starts a new turn; both stalled the audit. Hook count is now 3 events / 6 handlers. |
| Coverage leg (doc 05 §9, gate-spec) | coverage >= baseline for the same metric id | fails only when the count of untyped identifiers (total - covered) rises; percentage is reported | deleting well-typed code lowers type-coverage's percentage without adding an `any` (F01 wave 3: 96.36 -> 96.31), which would fail every cleanup |
| Skill injection (doc 11 header) | `!`ts-opt detect --brief`` | `!`ts-opt detect --brief 2>&1 \|\| true`` | in a `claude plugin eval` sandbox the plugin's bin/ is not on PATH and a failing `!` command aborted the whole invocation with zero turns; with `\|\| true` the block is empty and the skill's own fallback (`node ${CLAUDE_PLUGIN_ROOT}/bin/ts-opt`) takes over. In normal sessions the injected command still renders (verified live, rows 0.9 and M8-3) |
| Evals (doc 11 §10: seven cases) | seven cases | nine: adds `declaration-emit-quiet` and `ts7-compat-quiet` (negative trigger cases) | a description that fires on everything passes every positive trigger case; the two knowledge skills need a case that must stay silent |
| Skill tool grants (doc 11) | `allowed-tools: Bash(ts-opt *)` on every skill | audit, doctor and declaration-emit list the exact subcommands they use; fix and tsgo keep `Bash(ts-opt *)` | audit and doctor promise to be read-only; the grant must not pre-approve `plan lock`, `commit` or `toolbox install` |
| Subagent Bash (doc 03 H5) | rg, git grep\|ls-files\|log\|show\|blame\|diff, … | `git grep` is not offered; rg runs with `RIPGREP_CONFIG_PATH=catalog/rg-secrets.rc` (generated from `secret-paths.json`) and without `--hidden`, `--no-ignore`, `--pre`, `--follow`, `--search-zip` | `git grep` has no secret-path exclusion and reads ignored files; rg with the rc cannot report a hit inside a secret path (verified live) |
| `bin/` (doc 02 §1) | `bin/ts-opt` only | plus `bin/package.json` (`{"type":"commonjs"}`) | `bin/ts-opt` is extensionless CommonJS; an ancestor `package.json` with `"type":"module"` (a monorepo or the user's home) would otherwise make every `ts-opt` call fail |
| Subagent ts-opt calls (doc 03 H5) | one allow-list for plugin subagents | the triager may run `ts-opt verdict add\|status` and `ts-opt rule`; the architect `ts-opt proposal add`, `ts-opt rule` and `ts-opt findings show\|list`; rg accepts only negated globs (`!pattern`) | a positive `-g`/`--glob` is applied after the rc's secret exclusions and re-includes `.env`, key files and credentials (reproduced with ripgrep 15); each agent needs only its own recording command |
| Chunk contents (doc 04 §12) | `raw/chunks/Cnn.json` lists candidate ids | also a `records` array (id, rule, file, line, symbol, snippet, consumers) | `raw/` is gitignored and a hidden directory, and the subagent guard bans `--hidden` and `--no-ignore`, so a triager could not look a candidate up; live triagers spent calls on `cd` and retries |
| Command help (doc 02 §3.1) | not specified | `ts-opt <command> --help` prints the command's flags and exits 0 without running it | the flag used to be parsed and ignored, so `plan lock --help` locked the plan |
| `ts-opt commit --allow-protected <rule> --why` (doc 03 §4) | an audited override of a protected-path or edit-pattern refusal | not built | no case needed it; the answer to a refusal is to restore the file or skip the finding |
| Hook opt-outs (doc 03 §5) | `TS_OPTIMIZE_HOOKS=off` and `hooks.enabled=false` silence the nudges or all five handlers | both, and `hooks.fast_check=false`, silence the fast-typecheck hook only; the command, commit and subagent guards cannot be switched off from the repository | the guards are protections, and a switch in the audited repository would let repository text turn them off |
| Proposal diagrams (doc 04 §12) | `--mermaid` optional | required for `--recommendation STRONG` (exit 2 without it) | `codebase-health.md` promises a before/after diagram for every STRONG proposal; the live deep audit on F01 had 6 STRONG proposals and 5 diagrams |
